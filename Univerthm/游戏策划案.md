# 《Univerthm》游戏策划案

> 文档定位：现有三曲序章的策划基线，供剧情、谱面、界面与后续内容制作对齐。  
> 依据：当前 `game/` 工程、各 README、序章剧情文本与谱面包；旧版策划案仅用于参考 Stra、Kisai 两位角色的设定。  
> 状态说明：下文的「现有」指工程已实现；「规划」指建议的下一步；「待定」须由主创确认。

## 1. 项目定位

《Univerthm》是一款以键盘演奏为核心、用收藏档案推进短篇叙事的 Windows 音乐游戏。当前可玩内容为三首曲目的序章。玩家在曲目挑战中逐步解锁下一首歌，并通过 Stra 的笔记，拼出城市失声与夜空裂缝的经过。

**一句话体验目标：** 演奏仍在响起的曲目，记录一个逐渐失去声音的世界。

设计优先级：

1. **判定清楚。** 谱面位置与网页版制谱器预览保持一致，玩家能从按键与音符得到明确反馈。
2. **曲目先行。** 选曲、试听、演奏、结算构成主循环；剧情补充情绪和悬念，不打断正常读谱。
3. **发现有顺序。** 曲目、第三首的身份和对应笔记随通关逐步揭示，未解锁内容不在界面中剧透。
4. **内容可扩展。** 谱面包和纯文本档案沿用现有导入格式，新增内容尽量不要求改动游玩核心。

目标玩家是喜欢键盘音游、愿意反复挑战准确率与连击，同时接受轻量剧情收集的玩家。当前版本按单机体验设计，没有排行榜、社交或付费系统的策划承诺。

## 2. 玩家流程与核心循环

### 首次进入

光敏性警告 → 开屏画面 → 主界面 → 新手教程 → 选曲。教程在每次启动后首次进入主界面时自动出现一次；同一次运行中返回主界面不重复出现，也可从设置手动重看。

### 一局游戏

| 阶段 | 玩家行为 | 系统反馈与目的 |
| --- | --- | --- |
| 选曲 | 浏览曲名、曲绘、难度和最好成绩；选择可用曲目 | 播放试听，说明尚未解锁的条件 |
| 演奏 | 用键盘命中 `tap`、按住 `hold` | 判定环、打击音、连击、分数与准确率实时更新 |
| 结算 | 查看评级、准确率、连击、Early/Late 与最好成绩 | 记录正式游玩结果，解锁下一曲及对应笔记 |
| 收藏 | 在收藏品中查看立绘、曲绘与剧情档案 | 未获得的剧情只显示锁定槽位；已获得的可阅读全文 |
| 再挑战 | 重试当前谱面，或继续下一首 | 追求更高成绩，推进序章叙事 |

谱面没有血量失败：即使中途失误，也会完整播完并进入结算。自动演示供玩家观察谱面；须先完成至少一次正式游玩才能使用，且不写入通关、成绩或剧情掉落。

## 3. 世界与序章叙事

### 叙事前提

城市中的声音不是同时消失，而是按某种重复的间隔被逐段抹去。Stra 先察觉便利店提示音与脚步声的缺口，再把录音、星图与 Kisai 的观测联系起来，最终看见夜空裂开、黑洞扩张。笔记中的「七秒」和符号「Ж」是序章的核心线索。

叙事采用**第一人称笔记**：让玩家读到 Stra 当时看见、听见和无法确认的事，不在序章里提前解释黑洞的来源、Kisai 发来符号的原因或世界之后的结局。曲名提供情绪与章节节奏；这些原创剧情文本不代表第三方曲目的作者为本作世界观背书。

### 三曲结构（内部策划信息）

| 顺序 | 当前曲目 | 对应收藏档案 | 叙事任务 |
| --- | --- | --- | --- |
| 1 | `dream of utopia` | `Stra的笔记#1 · 失拍` | 用细小的日常失声建立异常，让玩家先怀疑感官，再看到可记录的空白 |
| 2 | `万日存在恐怖症` | `Stra的笔记#2 · 裂缝` | 把异常从声音扩展到时间与天空，建立 Stra 与 Kisai 的观测联系 |
| 3 | `《Ж》` | `Stra的笔记#3 · 最后七秒` | 让裂缝变成不可回避的黑洞事件，以「记录下一拍」作为序章收束 |

第三首在玩家首次打出成绩之前，于选曲页显示为 `???`，遮住曲绘并停用试听。其首次进入还会显示警告、经过黑幕与解锁动画；这一趟不能用 `Esc` 暂停或退出，直到结算才记录正式踏入。该限制已有实现，但后续可评估它对玩家退出预期和可访问性的影响。

### 叙事载体

- **现有：** 三篇 UTF-8 文本存于 `game/剧情/序章/`，按[剧情收录规则](game/剧情/README.md)随选曲顺序逐篇通关掉落；未获得时可看到锁定档案，不能读到标题与正文。
- **现有：** 收藏品「其他」分类中的[《作者的话》](game/文档/作者的话.txt)为常驻文档，无需通关；它不占用三首歌的剧情掉落位置。
- **规划：** 若增加章节，应为每首正式曲目明确配置对应档案，而不是长期依赖“第 N 首对应自然排序第 N 篇”的隐式关系；这样可避免自定义文本或改名扰乱掉落顺序。

## 4. 角色设计

| 角色 | 已有设定与视觉 | 序章中的作用 | 后续创作边界 |
| --- | --- | --- | --- |
| **Stra · 音律测绘者** | 银紫长发、紫瞳、白紫色宇航风外套，常持星图平板；主界面默认角色，亦是三篇笔记的作者 | 从日常声响的缺口出发，靠录音、星图与敲击记下正在消失的节奏；玩家主要通过她的记录理解事件 | 保持第一人称观察和不确定感，不在尚未铺垫的章节中突然给出全知解释 |
| **Kisai · 观测者** | 当前立绘为黑色衣装、紫色星云斗篷与环状光效；主界面可切换展示 | 对照重复出现的七秒空白，向 Stra 提供外部观测；第三篇笔记中发来符号「Ж」 | 目前不确定其消息来源、掌握的知识及后续行动，避免直接写成幕后操控者或问题答案 |

旧策划案对 Kisai 的关系说明仅有「我的舍友」一句，缺少明确的叙事视角；本案暂把二人定义为保持联络的观测伙伴，**是否为舍友待主创确认**。两人的现用立绘分别偏二次元插画与写实人像；后续增加角色画面时，应先决定保留这种反差还是统一美术语言。

## 5. 游玩与成绩规则

### 输入和谱面

- Windows 键盘为当前主要输入：默认 `A S D F` 与 `J K L ;` 对应左右判定区；判定区为 `none` 的轨道可接受任意有效键。另有简化键位预设，当前没有自由改键。
- 谱面支持 `tap` 和 `hold`。`hold` 的头部命中后，只要仍有任意键按下就持续保持；所有键松开才中断。
- 舞台固定 16:9，位置、线宽和剔除规则与网页版制谱器预览对应。游玩 HUD 保留进度、连击、分数、准确率、曲名和等级，不用额外信息遮挡音符。

### 判定和目标

| 判定 | 与目标时刻的差值 | 准确率权重 |
| --- | ---: | ---: |
| PERFECT+ | ≤55 ms | 100% |
| PERFECT | ≤80 ms | 100% |
| GOOD | ≤140 ms | 75% |
| BAD | ≤220 ms | 0% |
| MISS | 超出窗口或漏判 | 0% |

结算分数由判定权重和 PERFECT+ 数量决定，理论满分 **1,010,000**，没有连击分数加成。评级按准确率划分：S ≥96%、A ≥92%、B ≥85%、C ≥75%，其余为 D。结算显示 `ALL PERFECT+`、`ALL PERFECT`、`FULL COMBO` 等达成徽章。最好成绩按谱面保存，个人资料展示游玩次数、平均分和平均准确率。

## 6. 界面、声音与反馈

- **视觉：** 非游玩界面使用深空、黑洞、紫色霓虹与切角面板；游玩舞台保持简洁，让音符和判定优先。间歇性故障效果只在非正式演奏状态出现，避免干扰读谱。
- **声音：** 原创主菜单曲《Diffusion》从开屏淡入并延续到主界面；进入选曲后由曲目试听接管。结算音乐只播一次。设置分别控制音乐和打击音音量。
- **选曲反馈：** 已选歌曲显示曲绘、难度、时长和 BEST；锁定曲目说明解锁前提。第三首在首打前连背景、试听和详情都不能泄露信息。
- **可读性：** 长篇教程图在滚动弹窗内阅读；剧情以标题、摘要和全文阅读区呈现，支持滚轮与键盘翻页。16:9 窗口等比缩放，可用 `F11` 全屏。

## 7. 内容制作与交付规则

| 内容 | 当前入口 | 制作要求 |
| --- | --- | --- |
| 正式谱面 | `game/charts/` 的三份 `rchart v3` zip | 曲名、作者、难度、音频与曲绘元数据完整；实机核对试听与判定同步 |
| 剧情 | `game/剧情/` 下的 UTF-8 `.txt` | 标题与正文分段清晰；每首正式曲目的掉落关系可追踪，隐藏内容不在锁定态泄露 |
| 玩家导入 | `user://charts/`、`user://剧情/` | 导入失败应给出可理解的提示；自定义内容不应改变正式章节的掉落顺序 |
| 作者与授权说明 | `game/文档/作者的话.txt`、`game/README.md` | 文案保持一致，发行版本包含文档资源 |

当前三首曲目的谱面由宋云舒制作，主菜单音乐《Diffusion》由曹瑾容原创作曲、编曲。特别感谢何天泽（@D-E-R-E-L-I-C-T）提供音效支持。曲目音频与部分曲绘为第三方素材，项目目前仅供非商业学习交流；**公开发布或再次分发前必须取得相应授权，或移除、替换相关素材**。具体署名与联系渠道以[《作者的话》](game/文档/作者的话.txt)为准。

## 8. 下一阶段与验收

### 序章打磨（近期）

- 用全新存档完整走通三曲：教程出现、逐曲解锁、第三首首踏、三篇笔记掉落、作者文档可读。
- 在 1280×720、1920×1080 和全屏模式检查选曲、游玩、结算与长文本阅读的布局。
- 核对三首歌曲的音频、曲绘、谱面包和导出资源；在发布前处理第三方素材授权。
- 确认 Kisai 的人物关系、与「Ж」的联系，以及两位角色是否采用统一画风。

### 内容扩展（规划）

- 确定下一章节的曲目数量、叙事终点和每首曲目的独立档案，再制作谱面与文本。
- 将正式曲目与剧情掉落改为显式配置，制定旧存档迁移方式；保证既有玩家的解锁记录不丢失。
- 如扩展故事板、剧情 CG 或新的输入方式，先做一首歌的可玩样例，再决定是否推广到全章。

**版本验收底线：** 一名没有读过 README 的玩家，能在游戏内理解按键和解锁条件，完成三首歌，并在收藏品中读到对应剧情；旧存档与新存档都能正常进入主界面，导出的 Windows 版本包含三首正式谱面、三篇笔记和《作者的话》。

## 9. 待主创确认

1. Kisai 与 Stra 是否为舍友，以及 Kisai 为何能够观测重复的七秒空白。
2. 「Ж」在世界观中的确切含义；序章应保留悬念到什么程度。
3. 两位角色立绘的画风差异是否为有意设计。
4. 第三首首次进入时禁止 `Esc` 的规则是否保留，是否需要更明确的进入前提示。
5. 后续章节是继续 Stra 的笔记视角，还是加入 Kisai 的观测记录。
